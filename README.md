# YouTube 视频下载

适用于 Chromium 116 及以上版本的 Chrome 和 Edge。扩展可加载 YouTube 视频、Shorts 和公开播放列表，支持勾选下载、选择清晰度、保留声音和嵌入自动字幕，统一保存为 MP4。

## 安装与升级

1. 解压 `youtube-video-downloader-v2.0.2.zip`。从项目构建时，压缩包输出到 `dist/`。
2. 打开 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions`，启用「开发者模式」。
3. 点击「加载未打包的扩展程序」，选择解压后包含 `manifest.json` 的目录。
4. 在浏览器工具栏打开扩展。可以通过浏览器的扩展图标将「YouTube 视频下载」固定到工具栏。

ZIP 自带下载和音视频处理组件，安装步骤在浏览器内完成。

更新时，把新版文件解压到原来加载的目录并点击扩展卡片上的「重新加载」。如果解压到了另一目录，就加载新目录。结束当前下载后再重新加载扩展。

## 下载与设置

1. 打开扩展，确认输入框中的当前 YouTube 链接，或粘贴视频、Shorts、`youtu.be` 短链接或公开播放列表链接。链接同时包含视频和播放列表时，扩展会加载播放列表。
2. 点击「加载视频列表」。单条视频默认勾选。播放列表可以逐条勾选，也可以使用「全选」勾选可下载的条目。
3. 在列表下方设置清晰度、声音和字幕。所选设置用于本次勾选的全部视频。
4. 点击「下载所选」。列表按原顺序处理，显示当前进度、完成状态或失败原因。关闭弹窗后，任务会在浏览器内继续，重新打开即可查看进度。

### 清晰度、声音和字幕

| 设置 | 行为 |
| --- | --- |
| 最佳原画 | 使用浏览器可获取的最高源清晰度 |
| 指定清晰度 | 可选 4K（2160p）、2K（1440p）、1080p、720p、480p、360p、240p、144p |
| 包含声音 | 默认开启。取消勾选可保存静音 MP4 |
| 包含 YouTube 自动字幕 | 默认关闭。勾选后，扩展会将 YouTube 已提供的自动字幕作为 WebVTT 轨道写入 MP4 |

选定的分辨率高于可用源时，扩展会保持画面比例并尝试放大。画面细节取决于原视频。若浏览器无法编码更高的分辨率，扩展会尝试用源清晰度保存，并在条目上标明实际结果。

播放时，可在支持 MP4 内嵌 WebVTT 的播放器里开启或关闭字幕。如果对应视频只有人工字幕，或自动字幕读取失败，扩展会保存视频并在列表中提示。

### 查看文件和取消下载

- 文件保存在浏览器设置的下载目录下的 `YouTube` 文件夹。播放列表会创建同名子文件夹，文件名包含播放列表顺序。也可以从浏览器的下载记录打开文件位置。
- 下载、获取字幕、合并、调整分辨率或保存期间，都可点击「取消下载」。扩展会停止当前视频及本批次剩余任务，保留已经保存的文件。
- 取消后可以重新勾选需要下载的条目，调整清晰度，再开始新一批下载。

## 使用常见问题

| 现象 | 处理方法 |
| --- | --- |
| 提示「本机下载器未注册」 | 在扩展管理页确认已加载 2.0 系列扩展，并从对应工具栏图标打开最新版本 |
| 进度停留在「正在处理」 | 音视频合并、分辨率调整和字幕嵌入都在浏览器里完成。高分辨率视频处理时间较长，可等待处理完成，或取消后改选较低清晰度 |
| 列表中的视频不可下载 | 查看该条的可用状态或失败原因。部分视频的公开媒体流不可用，直播中或尚未播出的条目也可能无法下载 |
| 下载后播放器里找不到字幕 | 先确认条目显示「已嵌入自动字幕」，再在支持 MP4 内嵌 WebVTT 的播放器中打开字幕菜单 |

## 开发历程

### 项目起点

项目起于一个实际需求。Chrome 网上应用店把提供 YouTube 视频下载列为扩展被拒绝或下架的常见原因，商店里的通用视频下载器因而通常不提供此功能。项目选择独立维护并以 ZIP 分发，用户解压后可在浏览器中本地加载。[Chrome 网上应用店审核说明](https://developer.chrome.com/docs/webstore/troubleshooting#prohibited-products) · [商店扩展示例](https://chromewebstore.google.com/detail/video-download-helper/lmjnegcaeklhafolokijcfjliaokphfk)

### 早期本机下载器

早期方案把弹窗作为控制面板，下载和处理交由本机进程。仓库保留的 `install.py` 会检查 macOS 上的 yt-dlp、FFmpeg 和 Deno，复制 Python 宿主并生成启动器，再向 Chrome 或 Edge 注册 Native Messaging 宿主。注册文件的 `allowed_origins` 绑定具体扩展 ID，所以加载目录或浏览器环境改变导致扩展 ID 变化时，旧注册可能无法使用。

本机宿主 `host/host.py` 通过标准输入输出交换带长度前缀的 JSON，调用 yt-dlp 下载，并解析逐条和字节进度后回传给弹窗。这个方案可以复用成熟的媒体工具，但把依赖安装、浏览器注册和扩展 ID 配置变成了用户的安装步骤。「本机下载器未注册」就是宿主未能连接时的表现。现有发布包中最早可确认的版本号是 2.0.0，早期宿主阶段没有可核实的独立发布号。

### 2.0.0：播放列表优先与纯浏览器运行

早期弹窗有宽度过窄、标题和按钮换行的问题。新版在 `popup.css` 中给页面主体设置 680 像素宽度，让浏览器测量工具栏弹窗时得到明确的内容宽度。列表改为独立滚动区域，下载设置放在列表下方。交互从「下载单条」或「下载整个列表」调整为先加载条目、再勾选并设置本批次的清晰度和声音。列表行独立显示下载、处理和保存状态。

为免去本机注册，2.0.0 将媒体识别、分轨合并、转封装和调整分辨率移到扩展内部，所需 JS 和 WebAssembly 随 ZIP 交付。与此同时，符合选项的现成 MP4 仍由浏览器直接下载。两条路径最后都使用 Chrome 下载 API 保存文件，只有需要改变内容或容器时才走扩展内的媒体处理。

MP4 成为统一输出。YouTube 提供的流可能是 MP4，也可能是 WebM，部分格式还将视频和音频分开。更改扩展名无法改变容器内容，因此 WebM 输入需要实际转封装，轨道不兼容时还需要重新编码。2K、4K 分别对应 1440p、2160p。目标清晰度高于源时，扩展按比例放大并尝试编码，失败时尝试以源画质输出，再在界面标明实际结果。

### 2.0.1：取消贯穿整条下载链路

最初的进度显示只能观察任务。用户需要在大文件下载或 4K 放大过程中停下来，改选分辨率后再试。于是 2.0.1 为每批下载建立取消信号，贯穿请求、转码和 Chrome 保存阶段。取消以本批次为单位，已保存文件继续保留，当前条目和后续排队条目停止。队列在资源清理结束后重新开放下载选项。

### 2.0.2：加入可切换的自动字幕

用户可以决定是否将 YouTube 自动字幕合入视频。2.0.2 新增默认关闭的复选框，将现有字幕作为 MP4 内的独立 WebVTT 轨道。内嵌轨道允许播放器切换显示，也允许保持视频画面不变。需求中的「自动字幕」按 YouTube 轨道元数据判定，人工字幕与自动翻译不在这一选项的范围内。有可用字幕时，原本可直下的 MP4 也需进入封装路径，以写入新轨道。

验证中观察到，同一视频的 WEB 和移动播放器响应可能提供不同的字幕信息。可用自动字幕来自现有移动播放器响应中的轨道元数据，扩展读到有效 WebVTT 后再安排封装。缺少轨道或读取失败时，保留正常视频下载路径并显示条目提示。

### 弹窗、服务工作线程和离屏文档

弹窗会随用户操作开关，任务放在由服务工作线程按需创建的离屏文档里执行。离屏文档能持续处理浏览器媒体 API，并创建交给下载 API 的 Blob URL。服务工作线程集中代理需要扩展权限的下载操作，按发送方页面区分弹窗命令和离屏请求。

执行器是队列状态的写入方。每次发布都会快照列表和设置，串行写入 `chrome.storage.session`。弹窗订阅状态变化，并读取存储中的初始快照。关掉弹窗可以继续同一批任务。离屏文档重新创建并读取会话时，会将遗留的进行中状态标记为中断。会话状态用于恢复界面，扩展没有跨浏览器重启的断点续传机制。

### 目录、格式与播放地址

加载列表时只读目录信息。单条视频读取标题，播放列表使用 continuation 分页，保留原有顺序与不可下载条目。实现将列表限制在 5,000 条、最多 100 页，并在分页未新增条目时停止。预览和实际下载分开，勾选后才逐条获取流地址，避免在加载列表时为所有视频解析媒体格式。

下载时并行查询 MWEB、iOS 和 Android 播放器响应，汇总其中能识别的 MP4 和 WebM 流，筛掉声明为 DRM、直播分片等不适用的格式。元数据请求使用无凭据的会话，会话所需的 API Key 在运行时从 YouTube 自己的配置中读取，仓库和构建产物都不写入固定密钥。只有需要处理播放器签名或 `n` 参数时才载入播放器转换逻辑，YouTube.js 提取必要代码，QuickJS 在无浏览器宿主对象的 WebAssembly VM 中执行，并限制内存、栈和执行时间。解析后的媒体地址须通过 Googlevideo HTTPS 地址校验。

服务工作线程只为扩展自身发往指定 YouTube API 和 Googlevideo 媒体端点的请求注册请求头规则。最终下载只接受经过校验的媒体地址或本扩展的 Blob URL，文件名固定放在 `YouTube/` 下，按标题、视频 ID 和播放列表顺序命名，重名由 Chrome 追加编号。

## 下载原理

### 清晰度、声音与路径选择

`downloadPlans()` 使用格式标记的清晰度，缺失时使用宽高的较短边。选择「最佳原画」时优先较高的源清晰度。指定目标时，排序先选原始分辨率完全匹配的流，再选可缩小的最接近高分辨率，最后考虑从最高的低分辨率放大。相同清晰度下优先直下、MP4 和帧率等条件。

包含声音时，优先保留媒体原有的音轨。遇到独立视频流时，音轨候选优先考虑原声或默认轨、非动态范围压缩版本、MP4 容器和较高码率。关闭声音时，已有静音的合适 MP4 可以直接保存，带声音的输入则需移除音轨。

| 场景 | 路径 |
| --- | --- |
| 源为 MP4，清晰度及声音符合要求，且无可嵌入字幕 | 由 Chrome 下载 API 保存源文件 |
| 音视频分轨或需要去声 | 在扩展内选取并封装所需轨道 |
| 源为 WebM | 转为 MP4，按编码兼容性复用或转码 |
| 源分辨率与目标不同 | 维持比例并重新编码，竖屏以画面短边为目标 |
| 获取到自动字幕 | 写入 MP4 字幕轨道，可与以上处理合并完成 |

每个条目最多尝试前八个候选。给定候选的放大过程失败时，内部可以用已取得的媒体尝试源清晰度输出，避免为了这一回退重复取流。批次取消会终止候选重试和画质回退。

### 浏览器内媒体处理

1. **获取**。用 HTTP Range 分段读取媒体，已知长度时以 8 MiB 为请求窗口，并检查地址、内容类型、范围和接收字节。视频与独立音频可并行取得，单轨出错时中止同组请求。超过设定的无数据时间会触发超时。
2. **缓冲**。流式写入扩展源的 OPFS 临时文件，使长视频无需整段放入 JS 堆。每个处理任务有独立目录，保存或失败时清理。离屏任务首次打开临时根目录时，也会清理之前留下的目录。
3. **处理**。Mediabunny 打开输入并组装 MP4。兼容轨道可直接封装，需要改尺寸时使用浏览器支持的编码器。宽高取为偶数，首选可用的 AVC 编码，具体能力取决于系统和浏览器的 WebCodecs 实现。
4. **保存**。MP4 完成后创建 Blob URL，由服务工作线程交给 Chrome 下载。直到 Chrome 确认完成或取消，才释放 URL 和临时文件。

直下进度来自 Chrome 的已收字节与总字节。处理路径的百分比综合多个阶段，取流占约 0–72%，媒体处理从 73% 开始，保存从 95% 开始。总字节未知时显示不确定进度，Chrome 确认完成后才显示 100%。

### 自动字幕如何与 MP4 对齐

程序从播放器响应提取 `kind === "asr"` 的轨道，在确认字幕地址、去重后请求 WebVTT。它检查正文具有 WebVTT 文件头和时间段，避免把空响应误当成有字幕。字幕时间段沿用视频时间线，通过 Mediabunny 的 `TextSubtitleSource` 写入独立 MP4 轨道。播放时字幕显示由支持该轨道格式的播放器控制。扩展对未发布字幕的视频不做语音识别。

### 取消、清理与任务结果

每次开始下载创建一个批次 `AbortController`。点击取消时，队列先进入 `canceling`，拒绝继续修改设置或开启新任务。正在发生的播放器、字幕和媒体请求收到取消信号。编码阶段停止转换器并释放输出资源。直下或保存阶段用 Chrome 下载 ID 请求取消，之后查询最终状态。如果 Chrome 已经先一步确认完成，该文件仍计为已完成。

取消后的临时文件通过处理函数的清理逻辑删除，未完成的队列条目标记为已取消。普通网络或格式错误按条记录，并继续处理其他已选条目。取消由用户发起，整个批次随之停止。

## 构建与发布

构建需要 Node.js、npm 和命令行 `zip`，本项目使用 Node.js 24 做构建验证。浏览器运行基线是 Chromium 116。以下命令在包含 `package.json`、`scripts/` 和 `tests/` 的项目目录执行。安装 ZIP 包含运行所需的扩展文件与文档，需要重新构建时使用完整项目目录。

```sh
npm ci
npm test
npm run build
```

构建脚本使用 esbuild 生成 `extension/vendor/` 下的库文件，复制 QuickJS WASM 并汇总第三方许可。打包时会剥离 YouTube.js 依赖中内置的 API Key 字面量；会话配置改由扩展在运行时从 YouTube 获取，因此不需要在环境变量或 GitHub Secrets 中配置密钥。开发时加载项目的 `extension/` 目录，修改扩展源代码后从扩展管理页重新加载。修改依赖或打包入口后先重新构建。第三方许可随发布包放在 `vendor/LICENSES.txt`。`tests/no-secrets.test.js` 会检查源码和生成文件，发现 `AIza` 开头的 Google API Key 时让测试失败。

| 排查现象 | 首先检查 |
| --- | --- |
| 加载列表时失败 | 弹窗提示、服务工作线程消息转发、离屏文档的目录和分页请求 |
| 能列出视频但无法下载 | 播放器返回的可用流与报错、候选方案、Chrome 下载记录 |
| 放大后仍是源清晰度 | 条目提示、浏览器编码能力和媒体处理错误 |
| 没有字幕 | 播放器是否提供 ASR、字幕响应是否含有效时间段、输出中是否有 `wvtt` 轨道 |
| 取消后仍显示处理 | 队列是否处于清理阶段，检查 Chrome 下载是否已终止及 OPFS 是否有残留 |

回归验证应覆盖 MP4 直下、WebM 转 MP4、分轨合并、静音、清晰度调整、批量选择和取消。字幕分别检查可以取得、没有轨道和关闭选项的情况。此前的 Chrome 验证已经观察到进行中的直下和 4K 编码能够中断，取消后可改选 240p 完成下载。字幕功能也用公开视频确认了生成的 MP4 包含视频、音频与 `wvtt` 轨道。

功能版本更新时，同步 `extension/manifest.json`、`package.json`、`package-lock.json` 和文档中的发版信息。执行以下命令构建、归档并检查，以 2.0.2 为例。

```sh
npm test
npm run package
unzip -t dist/youtube-video-downloader-v2.0.2.zip
```

安装 ZIP 根目录包含 `manifest.json`、本 README 和 [版本更新记录](CHANGELOG.md)。最后解压到临时目录，在 Chrome 的扩展管理页加载一次，确认弹窗可以打开。

## 自动化发布

推送 `v<版本号>` 标签时，两个工作流会分别构建并发布同一份安装 ZIP。标签必须与 `extension/manifest.json` 中的 `version` 一致，例如清单版本为 `2.0.2` 时标签应为 `v2.0.2`。也可以在 Actions 页面手动触发并填写相同格式的标签。

- **Releases**：`release.yml` 执行 `npm ci`、`npm test`、`npm run build`、`npm run package`，然后在 GitHub Release 中附上 `youtube-video-downloader-v<版本号>.zip`。发布说明取自 `CHANGELOG.md` 中对应版本的小节；该版本没有小节时使用版本提示文案。重复发布会覆盖同名 ZIP 附件。
- **Packages**：`packages.yml` 将同一 ZIP 作为 OCI 制品推送到 GHCR，地址为 `ghcr.io/<owner>/<repo>:v<版本号>`。可以用 ORAS 下载：

```sh
oras pull ghcr.io/wty9sky/youtube-video-downloader:v2.0.2
```

两个工作流都使用仓库自带的 `GITHUB_TOKEN`，需要仓库的 Actions 权限允许读写（`contents: write` 用于 Releases，`packages: write` 用于 Packages）。如果仓库设置为只读权限，需要在仓库设置的 Actions 权限中调整后重新运行。发布前请确认 CHANGELOG 已包含该版本的内容，并在本地完成上面的构建与回归验证。
